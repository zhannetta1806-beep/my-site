# Отчёт
## Упаковка сайта в Docker

**Проект:** сайт Жанны Сабировой — санитарно-эпидемиологический аудит объектов  
**Дата проверки:** 15 октября 2026 г.  
**Адрес работающего сайта:** http://127.0.0.1:8088/

---

## 1. Цель

Собрать сайт в контейнер Docker, чтобы его можно было запустить одной командой на любом компьютере с Docker Desktop. Исходный код, пароль администратора и база заявок при этом остаются на компьютере и не попадают внутрь образа.

## 2. Что упаковано

Сайт состоит из двух частей:

- **Интерфейс** — React и Vite. Страницы: главная (`/`), услуги (`/admin`), реквизиты (`/admin/requisites`), заявки (`/crm`). Языки интерфейса: русский и казахский.
- **Сервер** — `server.py` на Python. Он отдаёт собранный сайт и API: услуги, заявки, вход администратора, счета. Данные лежат в SQLite-файле `data/crm.sqlite`.

В контейнере на момент проверки: **6 услуг и 3 заявки**. Вход администратора включён.

## 3. Файлы упаковки

| Файл | Зачем нужен |
|---|---|
| `Dockerfile` | Рецепт сборки образа в два этапа |
| `compose.yaml` | Запуск контейнера, порт и подключение папки с базой и файла `.env` |
| `.dockerignore` | Список того, что в образ копировать нельзя |
| `docker_entrypoint.py` | Проверка перед стартом: есть собранный сайт, файл `.env` и настоящая база |
| `.env.example` | Образец настроек без пароля |

## 4. Как устроена сборка

Сборка многоэтапная. В готовый образ попадает только то, что нужно для работы.

**Этап 1. Сборка интерфейса.**  
Образ `node:22-bookworm-slim`. Команды: `npm ci`, затем `npm run build`. Результат — папка `dist` с готовыми HTML, CSS и JavaScript. Компилятор Node.js в итоговый образ не входит.

**Этап 2. Сервер.**  
Образ `python:3.14-slim-bookworm`, внутри Python **3.14.8**. Копируются только `server.py`, `db.py`, `backup_db.py`, `docker_entrypoint.py` и готовая папка `dist`. Сервер слушает порт **8080** на всех интерфейсах контейнера (`0.0.0.0`), иначе снаружи до него не достучаться.

Имя образа: `my-site:local`.  
Размер: **202 390 390 байт** (около 193 МБ).  
Платформа: Linux amd64.

## 5. Что намеренно не попало в образ

`.dockerignore` исключает `node_modules`, `dist`, `data`, `.env`, `.git` и тесты.

- Пароль администратора лежит в `.env` на компьютере. В образ он не копируется. При запуске файл подключается к контейнеру только для чтения.
- База `data/crm.sqlite` тоже остаётся на компьютере и подключается отдельной папкой. Остановка контейнера базу не удаляет. Команду `docker compose down -v` использовать не нужно: база не лежит в томе Docker.
- Перед стартом `docker_entrypoint.py` проверяет, что база — существующий файл SQLite, и что `.env` подключён. Пустую базу контейнер сам не создаёт.

Снаружи контейнер опубликован только на этом компьютере: `127.0.0.1:8088` → порт `8080` внутри. Локальные порты разработки (Vite `5173` и обычный запуск Python `8080`) контейнер не занимает.

Процесс внутри контейнера сейчас работает от пользователя `root`. Для локальной учебной сборки этого достаточно. На чужом сервере процесс лучше запускать от отдельного пользователя без прав администратора.

## 6. Как запустить и остановить

Нужны Docker Desktop, заполненный файл `.env` и уже существующая база `data/crm.sqlite`.

Запуск из папки проекта:

```text
docker compose up --build -d
```

Сайт: http://127.0.0.1:8088/

Остановка без удаления базы:

```text
docker compose down
```

Контейнер и локальный `python server.py` одновременно запускать нельзя: оба пишут в один и тот же файл базы.
